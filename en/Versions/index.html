    v3.0.1 — 21/10/2026

    1. Architectural Overhaul & Performance Optimization (Zero-Lag & Zero-ANR)

    • 1.1. Eliminated BindableLayout bottleneck: Replaced non-virtualized folder hierarchy (which synchronously inflated and measured thousands of native Android views on the main UI looper, triggering 30s freezes and ANR "Application Not Responding" crashes) with a lightning-fast Drill-down navigation architecture.
    • 1.2. Shared native CollectionView virtualization: Displaying scores within any folder now directly leverages the library's virtualized native CollectionView. Opening the score library with 300+ scores dropped from 30 seconds down to < 0.1s (instantaneous), scrolling remains silky-smooth at 60/120 FPS, and score tap-to-open occurs immediately.
    • 1.3. Lightweight folders overview: Clean, virtualized folder card overview (FoldersOverviewView) with asynchronous in-memory counts (Task.Run) and an intuitive navigation breadcrumb with one-click return [ ⬅ All folders ].
    • 1.4. Complete list mode isolation: In List View mode, folder grouping logic is completely bypassed to ensure maximum performance.

    v3.0.0 — 21/10/2026

    1. Category System & Physical Storage Directories

    • 1.1. Level-1 categorization: Introduced Categories (thematic or stylistic folders) perfectly complementing existing multi-tag classifications. Each score belongs to a unique category (defaulting to "General").
    • 1.2. Physical disk synchronization: Score PDF and audio files are physically moved and kept in a dedicated subdirectory named after their category ([ScoresRootDirectory]/[Category]/[File.pdf]). Renaming, moving, or deleting categories reflects immediately on storage without losing any data or breaking setlist links.
    • 1.3. Streamlined editing and assignment: Assign categories directly when creating or editing a score (ScoreEditPage), with instant new folder creation dialog, plus a quick "Change folder / category" action from the score context menu (⋮) in the library.

    2. Dual Library View Modes (List View ⇄ Folder View)

    • 2.1. Instant List / Folder toggle: Added an interactive view toggle in the library header (ScoresPage) allowing seamless switching between classic flat List View and hierarchical Folder View.
    • 2.2. Accordion folder cards & intuitive navigation: In Folder View, scores are grouped into collapsible accordion cards showing score counts, expand/collapse chevrons, "Expand All" / "Collapse All" global controls, and direct folder creation.
    • 2.3. Contextual folder management: Dedicated folder context menu to rename, clear, or delete a category (safely returning orphaned scores to "General").
    • 2.4. Configurable user preference: Set your preferred default view mode (List View or Folder View) in Score Settings (SettingsScoresPage), persistently remembered.

    3. Ecosystem Compatibility & Full Internationalization

    • 3.1. Seamless backward compatibility: Automatic database schema migration on launch with zero user intervention required.
    • 3.2. Import / Export & Backup resilience: Embedded category metadata in score export archives, zip packages, and Wi-Fi Direct peer-to-peer sharing.
    • 3.3. Localization & Responsive UI: Fully localized across all 8 supported languages (fr, en, de, es, it, nl, pl, pt) with responsive sizing for both phones and tablets (OnIdiom).

    v2.8.4 — 18/10/2026

    1. Fix Context Menus on Smartphones (Vertical Line Glitch)

    • 1.1. WidthRequest mobile resolution: Fixed WidthRequest attributes on popups and context menus (ScoreMenuOverlay, SetlistMenuOverlay, DuplicateModal, TagsModal, MassActionsModal, PdfToolsModal, ModernImportModalCard). Missing Phone value inside OnIdiom evaluated to 0.0, drawing a 1px gray vertical line instead of displaying the modal card.
    • 1.2. Responsive modal width: Set Phone=-1 combined with HorizontalOptions="Fill", Margin="16,10" and MaximumWidthRequest="360", ensuring cards scale properly across all smartphone form factors.

    2. Setlist Editor Layout Overhaul (SetlistEditPage)

    • 2.1. Element overlap elimination: Restructured the setlist edit layout so that components never collide or overlap, even on compact smartphone screens.
    • 2.2. Streamlined status and lock controls: Placed the lock button (UNLOCKED 🔓) on the status header row, giving status chips their own dedicated row with properly scaled badge chips.
    • 2.3. Collapsible "Advanced options" section: Moved secondary options (Continuous mode, Pedal profile, and Delete Setlist) into an accordion section collapsed by default on mobile, freeing up over 400px of height for the score list.
    • 2.4. Safe bottom action bar: Removed the delete button from the bottom bar (now safely nested in advanced options), eliminating accidental taps and resolving the overlap with the "Scores" title and "+ Add" button.
    • 2.5. Date label formatting: Replaced the unformatted literal string {0:dd/MM/yyyy} with the localized label "Concert date".

    v2.8.3 — 18/10/2026

    1. Major Fix for Truncated Score Tags in Library

    • 1.1. Adaptive MeasureAllItems collection strategy: Replaced ItemSizingStrategy="MeasureFirstItem" with MeasureAllItems on the library's CollectionView. Previously, when the first score in the list had no tags, MAUI locked every item's height to the first item's reduced height (78px), squishing tags into flat lines without text.
    • 1.2. Dynamic score card sizing: Cards now dynamically adapt their height according to whether tags are present and the number of title lines, ensuring full visibility of tag badges, background colors, and labels.

    v2.8.2 — 18/10/2026

    1. Restored Vertical Mobility for Annotation Bar

    • 1.1. Dedicated drag handle ⠿ & gesture decoupling: Added a tactile drag handle ⠿ at the leading edge of the annotation bar equipped with its own dedicated PanGestureRecognizer. Enables smooth, unrestricted vertical dragging without horizontal gesture interception from the tool scroll container.
    • 1.2. Redundant drag surfaces: Central empty spacing and the border itself also preserve vertical panning within display boundaries.

    2. Tools Hub: Instant Dynamic Toggling & Layer Hierarchy

    • 2.1. Real-time dynamic visual feedback: Toggling any feature on or off (top score title, metronome, audio player, tuner, page indicator, annotations) immediately updates live on screen without waiting for the tools drawer to close.
    • 2.2. Optimized layer ordering (Z-Index): The tools drawer sits at the top foreground (ZIndex="1100"), while active tool components (ZIndex="1005") render in front of the tap-outside backdrop (ZIndex="998"), ensuring immediate visibility.

    3. Settings: Configurable "Quit" Navigation Tab

    • 3.1. Navigation bar personalization: Added an option under Settings › Application Behavior to toggle the visibility of the "Quit" tab in the main navigation bar (enabled by default).
    • 3.2. Android gesture integration: Users who rely on native Android back gestures can streamline their bottom navigation bar while preserving a direct one-tap exit button for users who prefer it.

    v2.8.1 — 18/10/2026

    1. Fix for Score Tags Display in the Scores List

    • 1.1. Restored HorizontalStackLayout container in score item cells: Resolved a known .NET MAUI Android measurement issue where FlexLayout inside CollectionView item templates and Auto grid rows collapsed vertically, crushing tags into thin 4px strips without visible text.
    • 1.2. Clean pill rendering and calibrated height: Tags properly display with their standard 22px height, rounded corners, and centered text (VerticalTextAlignment="Center").
    • 1.3. Harmonized score selection list: Applied the same reliable layout structure to the score picker (ScoreSelectionPage).

    v2.8.0 — 16/10/2026

    1. Full Smartphone Compatibility (Zero Regressions / Zero Impact on Tablet Experience)

    • 1.1. Non-Invasive Responsive Architecture via OnIdiom: Systematic adoption of .NET MAUI's OnIdiom (Phone vs Tablet) to deliver targeted UI/UX optimizations on smartphones without modifying any dimensions, margins, font sizes, or layout alignments on tablets.
    • 1.2. Annotation Toolbar in Mobile Portrait Orientation:
    • Full restructuring of the annotation toolbar into a two-column layout (Grid ColumnDefinitions="*, Auto").
    • Decoupled the ✕ close button into an outer, fixed right-aligned column: close button is always immediately visible and clickable on any phone width without requiring toolbar scrolling.
    • Sized tool buttons proportionally (28x32 on phone vs 34x36 on tablet) and organized highlight, draw, and text palette overlays into compact 2-row palettes (Orientation="{OnIdiom Phone=Vertical, Tablet=Horizontal}").
    • 1.3. Screen Headers & Search Bar (ScoresPage & SetlistsPage):
    • Compacted header buttons to 38x38 on smartphones (50x50 on tablet) with streamlined margins and spacing, restoring over 80 pixels of horizontal width to the SearchBar.
    • 1.4. Multi-Line Tag Chip Wrapping:
    • Replaced rigid HorizontalStackLayout with an auto-wrapping FlexLayout (Wrap="Wrap"). Tag chips flow naturally onto multiple rows on small screens without horizontal clipping.
    • 1.5. Lateral Alphabetical Fast-Scroller:
    • Adjusted width (22px on phone vs 28px on tablet) and score list right-margin, eliminating overlay conflicts with score text or thumbnails.
    • 1.6. Responsive Modals, Overlays & Action Cards:
    • Replaced fixed widths with fluid responsive cards (HorizontalOptions="{OnIdiom Phone=Fill, Tablet=Center}", WidthRequest="{OnIdiom Tablet=350/360/380}", adaptive 16px margins).
    • Replaced fixed HeightRequest on modal dialog buttons with MinimumHeightRequest and breathing vertical padding, enabling natural word-wrapping for long action labels without ellipses or truncation.

    2. Sheet Music Library: Rename Reliability & Reactivity

    • 2.1. Property Change Notifications (INotifyPropertyChanged): Added OnPropertyChanged notifications to Title and Composer on the Score model, ensuring instantaneous visual updates in collection views upon renaming.
    • 2.2. Search Filter Synchronization on Rename: Safely resets the active search query if the updated score title or composer no longer satisfies the filter term, preventing the score from disappearing unexpectedly after rename.

    v2.7.2 — 15/10/2026

    1. Major Performance Optimization: Sheet Music Open Time (4x to 8x Faster)

    • 1.1. Eliminated Cold Chromium/V8 WebView Startup Delay: The WebView component (used solely as a non-native fallback) is no longer statically instantiated in ViewerPage XAML layout. It is now lazy-loaded on demand, completely preventing Android Chromium engine cold initialization (saving 1.5 to 2.5 seconds per score opening).
    • 1.2. Bypassed Redundant PDF.js Asset Extraction: Deprecated extraction of bundled PDF.js archives from APK to local cache during native score opening. PDF.js is now only unpacked if the native Android PdfRenderer is unavailable.
